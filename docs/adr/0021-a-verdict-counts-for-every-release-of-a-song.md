# A verdict counts for every release of a song

Spotify gives each release of a recording its own track id: the album track, its remaster, the deluxe edition and a best-of are four tracks. Verdicts are keyed by track id (ADR 0005), so a playlist holding two releases of a song showed it twice in needle's Playlist review, and rating one left the other unrated: the listener was asked about a song they had just rated, as if the rating had been lost. haystack already keeps each track's ISRC, which names the recording and is the same on every release of it.

So from 0.8.0 the API knows the **Song**. A track card carries `song`, its ISRC (API feature `card.song`), and a Song's verdict is the newest current verdict on any of its tracks. A playlist card's `verdict`, `playlists` and `liked`, the playlist snapshot's `verdicts`, and which liked songs wait in Rate your likes all go by the Song. needle lists a Song once in a Playlist review and skips it when any of its releases has a verdict.

Storage doesn't change. Each verdict stays a row on the track it was given to, and its Spotify writes (the heart, Discoveries, To Rip) go to that track only. The Song's verdict is worked out when it is read.

**Why not Discoveries and Calibrate.** An offer or a pick is closed by a verdict on its own track (`_close_offer`, `judge_picks`). If a Discoveries card showed a verdict given to another release, needle would treat the offer as reviewed while haystack still had it open, and the clear before the next batch would record it as a no. So those two queues keep the track's own verdict. A candidate is a song the listener hasn't judged, so the two rarely differ there.

**Considered Options**: storing one verdict per ISRC (a migration of the log, Spotify writes that would need a track chosen per Song, and nothing to go on for a track with no ISRC); matching releases by artist and title (a live take, a remix or a radio edit would count as the same song; the ISRC is exact); fixing it in needle alone (needle sees only the playlists it fetched, so a verdict on a release in another playlist, or one given before the cards were cached, would still be missed).

**Consequences**: a track with no ISRC is a Song of its own, as before. A remaster that was given a new ISRC is a different Song, so it can still be asked about again. Two releases can carry different current verdicts, from before 0.8.0 or from the CLI: the newest one is the Song's, but each track keeps its own Spotify state, so an older 3★ on one release still keeps that track's heart. The re-ranker and the Baseline still count each track's own verdict, so a song rated on two releases counts twice there. An older needle ignores `song`: it lists each release, but a Playlist review started after one of them is rated skips them all.
